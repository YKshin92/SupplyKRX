# 자동매매 봇 (나무 PLUG) — 1단계: 규칙·안전장치

사이트 '전략 검증 · 시뮬레이션'의 운영 기본 규칙을 실제 계좌에서 그대로 따르는 봇이다. PC에서 돌린다.
**지금은 키 없이 만들 수 있는 부분까지(1단계)이며, 실제 주문 경로는 아직 쓰지 않는다.**

## 규칙 (시뮬레이션 기본값과 같음)
- 신호: 연기금 순매도 3억 이상, 3개월 무거래, 거래량 20일 평균 3배 이하(사이트 신호와 같은 자료).
- 매수: 신호 다음 거래일 시가. 주문 크기는 전날 종가 기준 평가자산의 25%, 최소 300만 원.
  - 현금이 모자라면 남은 현금이 300만 원 이상일 때만 그만큼 산다.
  - 여러 신호가 겹치면 신호일 수급 점수 높은 순으로 산다.
  - 이미 가진 종목은 더 사지 않는다.
  - 시가가 전날 종가보다 35% 넘게 벌어진 날은 사지 않는다.
- 매도:
  - 익절 +30%, 손절 −10%. 시가가 선을 넘으면 시가에 팔고, 장중에 닿으면 그 선에서 판다. 같은 날 양쪽에 닿으면 손절을 우선한다.
  - 보유 중 연기금 순매도가 신호일 순매수보다 크면 다음 거래일 시가에 전량 매도한다.
- 수수료 0.015%, 매도 수수료+거래세 0.215%를 시뮬레이션과 같이 반영한다.
- 아직 없는 것:
  - 쉬는 현금을 KOSPI200 ETF로 굴리는 기능
  - 기업행사(분할·무상증자) 자동 정산. 시가가 크게 끊기면 그 종목은 '확인 필요'로 멈추고 알린다.

## 검증
- `python -m trader.replay`: 하루씩 규칙을 돌리는 리플레이다. 사이트 시뮬레이션 엔진(`src/simulation-engine.ts`)과 거래를 하나씩 대조한다(`scripts/trader-parity.mjs`).
  - 실제 3년 자료(비공개, 2026-11-03): 시작일 2023-10-23 / 2026-01-01 × 설정 5가지 모두 일치했다. 거래 38건·17건, 최종 평가자산과 일별 현금·평가자산까지 같다.
  - 가상 자료(`tests/fixtures/trader-synthetic.json`, CI)는 다음 경우를 모두 지나가며 일치를 확인한다.
    - 연기금 순매도 청산
    - 갭 손절·익절, 양쪽 도달
    - 시가 단절, 현금 부족 대기·부분 매수
    - 보유 중 신호 제외, 점수 없음
- `tests/test_trader.py`: 실제 봇의 하루 흐름(`trader/bot.py`의 장 시작 → 장중 가격 → 마감)을 가상 계좌로 돌려도 리플레이와 같은 거래가 나오는지 확인한다.
  - 실제 3년 자료로도 기본 설정에서 일치했다.
  - 다만 상장폐지 추정 정산은 미래 자료를 보는 백테스트 전용 처리라서 봇에는 없다. 이 경우만 다르다.

## 안전장치
- 긴급 정지: `python -m trader.bot stop` / `resume`. 사이트 버튼은 2단계에서 붙인다. 정지 중에는 새 주문을 내지 않고 보유는 그대로 둔다.
- 하루 최대 매수 금액: 넘는 매수는 하지 않고 다음 거래일에 다시 본다.
- 모의투자 고정:
  - 기본은 모의 서버(moapi)와 모의 계좌(유형 03)만 허용한다.
  - 실전은 설정 `mode='live'`와 환경 변수 `TRADER_LIVE_ACCOUNT=<계좌번호>`를 사용자가 **둘 다** 직접 맞춰야 열린다.
  - 주소·계좌가 어긋나면 아무 호출도 하지 않고 멈춘다.
- 키는 공식 SDK가 PC의 `~/.nhplug/.env`에서 읽는다. 이 저장소·사이트·장부 어디에도 두지 않는다.
- 주문 접수 응답만으로 체결을 판단하지 않는다. 같은 응답 코드가 API마다 뜻이 다르기 때문이다. 체결은 잔고 조회로 맞춘다.

## 다음 단계
1. 사용자: [nhplug.com](https://www.nhplug.com/howto-use)에서 API 사용신청을 하고 앱키·시크릿과 모의투자 계좌를 준비한다.
2. 모의투자 연결:
   - 시세·잔고·체결 응답의 필드를 실제 응답으로 확인해 `PlugBroker`를 완성한다.
   - PC에 설치하고 장중 자동 실행을 붙인다.
   - 장 시작 전 계좌와 장부를 맞추는 단계를 넣는다.
3. 사이트 '자동매매'(관리자 전용) 탭은 화면(`src/AutoTrading.tsx`)과 API(`api/trading.js`)까지 만들었다. 탭은 현재 잔고 · 거래내역 · 매매 성과이고 긴급 정지 버튼이 있다.
   - 연결은 비공개 저장소 SupplyKRX-data의 `trading-state` 가지를 쓴다. 이 가지는 배포하지 않는다.
     - 봇이 `trading/state.json`을 올린다(`trader/report.py`, `trader/sync.py`).
     - 사이트의 정지·재개 버튼은 `trading-control.yml`을 실행해 `trading/control.json`에 기록한다.
     - 봇은 주문 직전마다 이 파일을 확인한다.
   - 사용자가 준비할 것:
     - PC용 GitHub 토큰: SupplyKRX-data 한 저장소, Contents 읽기·쓰기만. PC 환경 변수 `SUPPLYKRX_TRADER_TOKEN`에 넣는다.
     - 사이트 서버 토큰 `GITHUB_COLLECTION_TOKEN`에 Contents 읽기 권한 추가
4. 실전 전환은 모의 결과를 보고 사용자가 직접 한다.
